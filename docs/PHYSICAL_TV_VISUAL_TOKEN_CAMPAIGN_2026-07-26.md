# Physical-TV visual-token campaign

Date: 2026-07-26

Status: strict blocked plan; no physical-TV, participant, target-performance,
accessibility, accent-selection, or release result.

## Purpose

I-206 asks for more than another browser screenshot. The tracked plan turns the
current OCR-A, monochrome-plus-one-accent software contract into a campaign that
can distinguish desktop regression evidence from physical-panel evidence at a
real seating distance.

The campaign covers launcher Home, first-run setup, loading, manual pause,
tracking loss, profile portrait, retro library, recoverable errors, and
developer mode. Each surface must expose default, focused, fault, and recovery
states from the real shell rather than a lookalike fixture.

## Frozen matrix

The rendering matrix crosses:

- nine shell surfaces;
- cyan, amber, and violet candidate accents;
- standard and high-contrast modes;
- standard and reduced-motion modes;
- ordinary x86-64 Linux and Raspberry Pi 5/Hailo target classes;
- one selected primary television and one selected secondary panel role.

That yields 432 blocking cells and three valid runs per cell, or 1,296 physical
rendering runs. Grayscale/luminance review is mandatory for every focused state
so an accent hue cannot prove focus by itself. No surface, accent, target,
display, seating position, contrast mode, or aggregate average can rescue a
failed cell.

The performance lane contains 216 target/surface/accent/contrast/motion cells
and twenty valid runs per cell, or 4,320 runs. It records GPU frame time, FPS,
drops, memory, power, declared versus measured transition timing, and the
non-repeating reduced-motion behavior on the real target.

## Human observation boundary

The six controller-only tasks ask a participant to identify the current state,
find focus without color, read critical copy, activate the focused choice,
recover with Back/Home, and explain a fault plus its next safe action.

Both blocking persona classes and ordinary-vision, low-vision-protocol, and
color-vision-protocol strata remain required. Cohort sizes and valid task runs
are deliberately null until the owner approves a recruitment, consent/assent,
accessibility, and scoring protocol. The plan forbids diagnosing or inferring a
participant identity or medical condition.

## Evidence and privacy

Physical display captures must contain no people and must be cropped, redacted,
and stripped of EXIF. Participant names, faces, voices, exact ages, addresses,
diagnoses, stable identifiers, raw task recordings, and individual free text
cannot enter the repository or release evidence. Temporary collection requires
a separate consent, access-control, and deletion protocol.

## Claim boundary

The existing computed contrast, OCR-A parser, headless Chrome captures, and CSS
tests remain useful software regression evidence. They do not prove physical-TV
readability, focus visibility, comprehension, accessibility, animation comfort,
GPU performance, or release fitness. The plan cannot select which accents ship
or alter D-026, D-027, or D-117.

Execution remains blocked on the exact build, televisions, panel modes,
reference targets, room/light/distance/camera protocol, complete real shell
states, participant and accessibility protocols, instruments, schedules,
numeric gates, data handling, and physical/publication authority listed in
`OWNER_QUESTIONS_PHYSICAL_TV_VISUAL_TOKENS_2026-07-26.md`.
