# Owner questions from the RetroArch tranche

Last updated: 2026-07-23

No owner decision blocks the next software-only RetroArch work. Existing decisions define the Rust host, supervised local frontend, curated core/controller defaults, family-mode restrictions, rights policy, storage isolation, and branded launcher return.

Two product choices can wait until the integration is running on target Linux:

1. Should 2048 remain an internal qualification fixture, or become a visible starter-catalog game after its exact RetroArch/core artifacts, notices, controller behavior, and both architectures pass? It is currently labeled only as an uninstalled qualification candidate.
2. Outside family mode, should developer mode expose RetroArch's complete menu, or should every build retain the VCG-curated subset and require command-line/service access for deeper diagnostics? The safe reversible default is the curated subset everywhere.

Neither question authorizes downloading or distributing binaries, content, BIOS files, keys, artwork, or trademarks. Artifact selection and rights evidence remain engineering/review work before any distribution decision.
